## Map modes

Risk (avg score) · Health (band colors) · Projects (density quartiles) ·
Investigations (active case count). District click shows health, risk
distribution, expenditure, active investigations, and cross-filter links.
Centroid circles remain the fallback when boundaries are unavailable and the
rendering for project-point mode.

## Boundary data provenance

DataMeet India community maps, `Districts/Census_2011` (CC BY 4.0), 80/80
districts matched exactly once via a 13-name alias table; full provenance,
attribution requirements and dataset-vintage caveats in
[data/seed/boundaries/ATTRIBUTION.md](../data/seed/boundaries/ATTRIBUTION.md).
Attribution is displayed in the map's Leaflet control and returned by the
boundaries API.

## E2E architecture

Playwright + Chromium against a **production build** (`vite preview`, :4173)
and the real backend (:8000, started or reused). Single worker (shared dev
DB), OSM tiles route-blocked, reduced motion, traces on failure. Specs cover
auth, navigation/KPIs, projects, map + cross-filtering, the complete
investigation lifecycle (open → assign → playbook → Copilot → PDF download →
close with outcome → timeline), RBAC per role, and the model dashboard.
Investigation specs drive cases to a terminal state so reruns stay clean.
Prerequisite: Docker Postgres :5434 with demo-v2 + pipeline outputs + seeded
users (same as pytest).

## Pipeline/regeneration notes (M06/M07 interplay)

`run_pipeline` now detaches investigation pins (`risk_assessment_id`,
`alert_id`) before regenerating AI tables; the case's frozen
`priority_breakdown` preserves at-open evidence and case detail falls back to
the current assessment. Dataset regeneration still resets investigations
(documented M06 behavior).

## Known limitations after M07

- Boundaries are Census-2011 extents; post-2011 bifurcations are represented
  undivided (documented per district in ATTRIBUTION.md).
- Health-score weights are documented design choices pending real-data
  calibration; small portfolios are flagged low-confidence.
- Risk timeline still has a single point per project (each pipeline run
  replaces ai_assessments).
- Reports are generated on demand, not archived server-side.
- Playwright's backend web-server command is Windows-pathed (this dev
  machine); other platforms start the backend manually (reused automatically).
- Evaluation metrics shift slightly with run date (time-dependent features);
  see docs/MODEL_REGISTRY.md.
