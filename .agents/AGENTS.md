# Project Rules — DRISHTI (Team BiteCoder)

## Global Quality Standard — Enterprise & Government Grade

This application is a premium, government-grade, enterprise intelligence platform for serious institutional users.

Every page must independently achieve a 10/10 visual and UX standard.

### Core Brand Values
- **TRUST**
- **PRECISION**
- **AUTHORITY**
- **INTELLIGENCE**
- **TRANSPARENCY**
- **SECURITY**
- **DATA CREDIBILITY**

### Design Directives
- Do NOT produce generic SaaS UI or generic dashboard cards.
- Do NOT blindly use shadcn/default components.
- Do NOT make every page look identical.
- Do NOT overuse rounded cards or add decorative elements without purpose.
- Do NOT use excessive gradients, neon, or glassmorphism.
- Do NOT make it look like a startup landing page inside the application.
- Every page must have its own visual hierarchy appropriate to its purpose while remaining part of the same design language.

### 10/10 Page Evaluation Checklist
Every page must be evaluated against:
1. Visual hierarchy
2. Typography
3. Spacing
4. Information architecture
5. Data visualization
6. Component quality
7. Interaction quality
8. Micro-interactions
9. Loading/empty/error states
10. Accessibility
11. Responsive behavior
12. Government/enterprise credibility
13. Data clarity
14. Consistency
15. Attention to detail

**Rule:** FUNCTIONALITY + VISUAL POLISH + UX + CREDIBILITY = COMPLETE.

### Workflow Constraint
Before finishing any phase:
1. Inspect every affected page.
2. Compare against the 10/10 standard.
3. Identify weak areas and refine them.
4. Test and verify no existing functionality is broken.
5. **Never start the next phase automatically.**
